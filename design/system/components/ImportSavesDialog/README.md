Dialog that brings saves from a shared zip into GameSync: each kept as a named save, or used now with the save in place kept first.

**Since version 57** (KAN-166; a friend, 8 Oct 2026: "When user imports a save it should ask that would you like to backup your current save? and then you can replace the save or import as named save. It should be additive. There should a plus button that a user can use to add a tag to imported saves. Like if they added the tag jawad, there would be a small tag after PC NAME to show its relevant to that tag"): a ticked game this PC has chooses, under its name, **Keep as a named save** (the default, and all a game not installed here can do) or **Use it now**: its save is put in place at once, after the save in place is kept as a named save, Before the import (`#now`). Nothing is ever lost: importing only adds. **Tag** at the foot: + Add a tag opens a small field (`#tag`), and the tag, such as the friend's name, goes on every save the zip brings, shown after the PC's name wherever the save is listed (a game's saves, its named saves). The primary reads Import N saves; Done says which games use the imported save now and that their own is kept, or that they're named saves to restore when wanted. Provide `use` and `tag` to start from them, and `onImport(ids, use, tag)`.

Provide `zipName`, `from` (when it was packed), `items` (`{id, name, art, match: matched, not-installed or unknown, versions, size, warn?, removed?}`), `onImport(ids)` and `onClose`.

- Matched games add their saves as named saves, never current unless Use it now is picked. A not-installed game joins the library as Not installed, kept with the zip's rules and backed up only, and its saves wait until the game is found (built 1 Oct 2026). An unknown game, one whose saves this PC can't place, can't be ticked, and its `warn` says why.
- `warn` shows in `warn` under the game (a save made on another account may not load); `removed` shows in `danger` (a program file was left out).
- `blocked` (version 51, R16): a game with an anti-cheat, or that plays only online, can't be imported, whether this PC has it or not: it can't be ticked, its line reads "Can't be imported" and the reason shows in `danger` with the shield ("Has an anti-cheat, so its saves stay with the account that made them." or "Plays only online, so its saves stay with the account that made them."). Such a zip only comes from outside GameSync, as Share leaves those games out.
- The footer counts games and saves, says how many are used now, and that a save used now is put in place only after the one there is kept.

**Built** (version 58, 18 Oct 2026; KAN-166, SHARE-10): each save comes in as a named save, named as the sharer named it when it was a named save there (a zip carries that name since 18 Oct), else "Imported" and the day; it lists under the PC that made it, with the tag after its name. Use it now is on offer for a game here that's installed (one known only by its saves keeps them as named saves), and puts in the newest of the zip's saves for that game after the save in place is kept as the named save Before the import (none is kept when the game has no save on this PC yet); a file the game holds, or a refusal, leaves its own save as it was and says why, the imported saves kept named. Imported again, a save already in the history isn't added twice, but Use it now still puts it in place. The tag is one line, 24 characters at most. Done reads "Imported 4 saves into 3 games as named saves, tagged Jawad. Terraria is using the imported save now; your own is kept as a named save, Before the import."
