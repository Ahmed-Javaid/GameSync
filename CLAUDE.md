# GameSync

A Windows app that keeps game saves backed up and synced across a person's PCs, launches their games, and shows every problem on the game it belongs to. It replaces Ludusavi for the owner, whose main complaint was a folder-wide cloud "conflict" that never said which game. Free and open source (GitHub), for the owner and a few friends.

## Decisions so far

- **Stack:** C# on .NET 10, Avalonia UI in the owner's own style (dark first), SQLite, one self-contained exe, per-machine installer. Chosen over Tauri/Rust because the owner knows .NET and wants a future ASP.NET Core server to share code.
- **Cloud:** Google Drive first with the `drive.file` scope, through Google's official .NET client, not rclone (rclone's errors were opaque). Storage sits behind `IBlobStore` + `IVersionLog`, so S3/R2 and a later server plug in.
- **Encryption on Drive:** off (decided 2026-09-27), so the readable `latest/` folder and `restore.ps1` get saves back without GameSync. It may come later as an opt-in; `IBlobStore` stays able to take an encrypting wrapper.
- **Sync model:** per game, three-way (this PC vs cloud vs last synced base). Immutable versions with parents; a fork is a conflict. Files stored once by hash.
- **Multiple PCs:** yes (desktop and laptop). Portable paths, device IDs, now-playing marker in the cloud.
- **Conflicts:** newest save wins automatically and the loser is pinned with a Swap button. Never automatic on a first sync on a PC, when the newer side shrank by over half or is empty, when it changed outside a play session, or when the clock is off.
- **Retention:** every version is kept forever. Thinning is manual only, and pinned versions are never thinned.
- **Named saves (2026-09-27):** New named save… (Save as… until 2026-10-01; on a game's Named saves card) keeps the save under a name ("Before Lady Maria") as a pinned version on every PC, restorable in a step; folders the owner kept by hand (Bloodborne on shadPS4: `CUSA00207\<name>\SPRJ0005` beside the live `CUSA00207\SPRJ0005`) import as named saves without being touched. Since 2026-09-30 (the owner) named saves, Back up now and imports work before a game syncs: the first keeps it backed up only, not synced between PCs, until Sync between PCs. BAK-18 to BAK-20; design.md → Sync engine → Named saves.
- **Game updates:** when a game's build changes, the current save is snapshotted and pinned before the new build runs.
- **Daily backup:** the user sets the time; a missed run catches up about 10 minutes after the next sign-in.
- **Save discovery:** PCGamingWiki list (Ludusavi manifest), then engine rules, then name search, then learn mode (folder watcher, optional admin ETW tracer). Saves of games that aren't installed are found from the list too. Nothing syncs until confirmed; later finds are suggestions.
- **Rules travel with the saves (2026-09-28):** each version records its portable rules, so a PC without the game is offered them and one whose rules differ is told and asked (PC-04, R8). Registry keys are exported into a folder of GameSync's own that joins the game as a root (FIND-10).
- **Ludusavi import (2026-09-28):** ignore list, custom games, and each game's latest backup as a named save kept aside, never current by itself (ONB-04, reworded). Command line only since later that day: first run doesn't offer it, as almost nobody migrates that way.
- **Your own games and folders (2026-09-28):** Add a game or folder takes a name, a folder and optionally the program that uses it, and syncs it like a game, such as a Minecraft server's world: when that program closes, or once the folder has been quiet for 5 minutes (LIB-13). Built 2026-09-30: the other PC joins by adding its own folder under the same name, and a folder's spells of changes aren't play time. Store-cloud games read "Synced by Steam" (or Epic, Xbox) instead of "Backup only" (done 2026-09-28, app and command line).
- **Achievements (2026-09-28):** wanted, after v1: Steam's first, read from Steam's own files with no key; ACH-01 to ACH-04, design.md → Achievements. Their place on a game's page is drawn: the play bar and a card under About (2026-09-29).
- **Launcher:** own UI, replacing Playnite. Home and the game library are about games (art, play time, later achievements); saves live in the save manager, folders in Settings (the owner, 2026-09-28). Steam software (Wallpaper Engine) goes under the library's Software tab, and any game can be hidden from the launcher on a PC without changing its sync.
- **The library like Steam's (the owner's wishes, 2026-09-28; built 2026-09-29):** every game by name in a list beside the covers, with a search, a sort (Recently played, Name, Hours played, Recently added) and favourites first, favourites and the sort kept per PC; a click on any game opens its page beside the list (LIB-14 to LIB-18).
- **A game's page is about the game (the owner, 2026-09-29):** like Steam's, with a play bar, About from its Steam store page, a small Saves card and On this PC (LIB-19); the save work lives in the save manager (MGR-07). Every page below the rail has Back and a breadcrumb (LIB-21), and the screens follow Nielsen's heuristics and Shneiderman's golden rules (A11Y-05; design system README → Navigation and feedback).
- **Properties and choosing files (the owner, 2026-09-29):** every game has Properties like Steam's (LIB-20), with the program and launch options for a game in its own folder, per PC (PLAY-11), and which files are backed up (FIND-12), kept as the game's own rules so they travel with its saves (R8). The defaults every new game starts from go in Settings → What to back up (SET-06, designed, built with Settings).
- **Art and play from Steam, with as little contact as possible (2026-09-28):** art comes from the Steam client's own cache on the PC first; Steam's store is asked once per new game, by app ID only, for its type, its store page's basics (ART-09) and any art the client doesn't have, plus Steam's list of tag names once a month. Last played and hours come from Steam's local record. The fonts (Onest, JetBrains Mono, OFL) ship inside the app.
- **Windows:** 11 and 10 22H2 (decided 2026-09-28).
- **Look and theming:** launcher from the reference images, Console-style save manager; presets with a primary and a secondary colour, Dark, Light or Match Windows, pure black; status colours never follow the theme. Custom colours come later.
- **Glossy and Solid (2026-09-28):** two surface modes, saved per PC. Glossy shows a blurred copy of the game's art through the app: full glass on Home, the library (both since 2026-10-01, the owner), game detail, conflict and the save manager, a soft glow on first run and settings; a backdrop's colour is capped so one vivid colour can't flood the app (2026-10-01). Playing is Spotify's green since 2026-10-01 (the owner; design system version 24). Solid is the plain look. A fresh install starts in Glossy. Drawn on the mockups canvas; design.md → UI; LOOK-17, LOOK-18. Built 2026-09-28; `gamesync set surface glossy|solid` switches it until Settings has it.
- **Folders:** you choose the backup folder (moved with hash checks), how much history stays on the PC, game folders to scan, extra save folders, and where shared zips go.
- **Sharing:** Share selected or Share all into one zip; Import saves adds pinned versions only. Share all packs each game's current save; any version can be shared, even one only in the cloud, downloading only its files. Single-player saves and multiplayer world files can be shared; anti-cheat and online-only games can't (R16, 2026-09-28).
- **Tray icon (2026-09-28):** the mark in the taskbar's own white or black, with a badge in the status colours for working, needs you, offline and playing; Windows' own menu. The app closes its window to the tray and draws on the CPU so it waits small.
- **Friends and accounts (2026-09-28):** release builds carry the owner's Google client (never the public repo), so friends sign in with one click; one Google account per PC; English only in v1; Copy diagnostics in Settings; the performance targets PERF-01 to PERF-03 stand.
- **Cover art:** Steam's store API (`IStoreBrowseService/GetItems`, no key) by Steam app ID, including IDs from the save list; SteamGridDB only with the user's own key; a title cover when nothing matches. Cached locally, never synced. Since 2026-09-29 each game's cover, banner and logo can be the person's own image (Properties → Art, ART-06), checked like Steam's and kept on that PC only.
- **Games in their own folders and the game playing now (the owner, 2026-09-29):** the library has Installed and Local views, kept per PC (LIB-22); Local's Scan a folder for games… adds a game folder and scans the PC at once (LIB-23); a game found only by its saves has Locate the game… (LIB-24). A folder with no program of its own is looked into: one game in it is that game, named from inside; several are each a game; tools aren't games (LIB-28, 2026-09-30). Every installed game is watched, so the game playing now is Home's hero whether it syncs or not (PLAY-12); only games that sync pause the agent's disk work (BG-08), and Steam's software is never taken for a game. The save manager shows the backups' real space on their drive (MGR-03). An animated, PS4-like Home and friends' activity are open questions, to talk through later.

## Rules that must never break

- Only save data moves. Never back up or restore program files (check the extension and the Windows program header).
- Restores write only inside the game's approved folders; registry restores only under the game's own key.
- Never touch a running game beyond watching it: `PROCESS_QUERY_LIMITED_INFORMATION` at most, no memory access, injection, hooks, overlays, suspension, or kernel driver. No learn mode for games that ship an anti-cheat, and launch those only through their official route.
- A missing folder or unplugged drive is never treated as deleted; changes made outside a play session are held for review; nothing is overwritten without a snapshot first.
- Keep crack or emulator save-folder lists out of the repo; users add such folders in their own settings.
- The full list is R1–R21 in `docs/design.md` → Safety and security rules. Each rule gets an automated test.
