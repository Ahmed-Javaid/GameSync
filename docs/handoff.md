## How to work

```powershell
dotnet build GameSync.sln
dotnet test GameSync.sln
# The app on a scratch data folder, so nothing of the owner's is touched (see below for making one).
& src\GameSync.App\bin\Debug\net10.0-windows10.0.19041.0\GameSync.Tray.exe --data <scratch>
# Render pages to PNG files: the component galleries, or Home and the library from a data folder's games and art.
dotnet run --project tools/GameSync.Snapshots -- <output folder> gallery gallery2 gallery3
dotnet run --project tools/GameSync.Snapshots -- <output folder> --data <data folder> home library library-full library-hidden
# The real window in Glossy over the last-played game's art, one per strength (light mode shows it Solid).
dotnet run --project tools/GameSync.Snapshots -- <output folder> --data <data folder> glossy-home glossy-library glossy-console glossy-settings
# Any window size, as a maximized window's page (the screen less the taskbar): check every screen at several.
dotnet run --project tools/GameSync.Snapshots -- <output folder> --data <data folder> --size 1920x1152 glossy-home
# The library with a search typed, and a game's page beside the list with its places, saves and history (--game, or the hero game).
dotnet run --project tools/GameSync.Snapshots -- <output folder> --data <data folder> --game lantern-keep library-search library-game glossy-game
# The design system: serve the offline viewer (http://127.0.0.1:5178), or render cards to PNG at full size with Edge, to compare with the app.
node tools/design-system/serve.js
node tools/design-system/shoot.js <output folder> [--theme dark] [--surface glossy|solid] LibraryScreen GameDetailScreen
```

- **Real data without touching the owner's**: make a scratch data folder with `gamesync --data <scratch> init --remote <scratch>\cloud --name DESKTOP`, `add-folder E:\Games`, `add-folder G:\`, `scan` (reads only), then `gamesync --data <scratch> art`. Render with `--data <scratch>`, or open the app with it. **Never confirm games in a scratch folder the app opens**: the app's agent syncs confirmed games by itself, and that copies real saves.
- **A synced game with history, safely**: add a stand-in whose saves live in the scratchpad (`gamesync --data <scratch> add-game lantern-keep --title "Lantern Keep" --root saves=<scratch>\fake-saves\Lantern Keep\Saves`), write a file there, `sync lantern-keep`, change it, `backup`, `save lantern-keep "Before the Warden"`, `approve`. Its page then has versions, a named save and a log, and Restore on it writes only into the scratchpad. Render it with `--game lantern-keep library-game`.
- **Windows opened for a test appear in front of the owner**, who may be using the PC: keep them brief and close them after (`Stop-Process` on the scratch app's id; it's not the owner's). On 30 Sep a test window was closed by hand halfway through (most likely by the owner): the app stays in the tray, and starting it again with the same `--data` brings the window back where it was.
- **First run on a fresh scratch folder**: make an empty data folder and copy `savelist.json.gz` and `savelist.etag` into it from a scratch folder that has them (otherwise the first scan downloads the save list). Make a scratchpad games folder with a stand-in: `<scratch>\fr-games\<name>\<name>.exe` (a few KB starting `MZ`) and `Saves\slot1.sav`. Give the program a name no real game has: the save list matches a game in its own folder by its program's name too, so `Lantern.exe` became the real game "Lantern". Start the test copy with `--data <folder>`.
  - Drive it with `tools\window\uia.ps1`: `invoke` for buttons, `toggle` (added 30 Sep) for check boxes and switches, and `picker.ps1` for Add a game folder (picker title "A folder your games") and the cloud folder ("A folder every PC can reach").
  - **Untick every group of real games** (their boxes are named "Untick every game in Sync" and so on) and tick only the stand-in, then **turn both switches off** in Backups and startup before Start using GameSync.
  - The scan itself only reads, and `FirstRun.WindowsSchedule` refuses a data folder that isn't the usual one anyway.
- **Talking to a running app**: the pipe is named `GameSync-` plus the first 20 hex digits of SHA-256 of `<user SID>|<DATA FOLDER, full path, upper case, no trailing \>`; send one line (`status`, `show`, `look`, `quit`) and read one line back. `AppPipe.SendAsync` does it from C#.
- **Commands for the owner** are for Windows PowerShell: a quoted program path needs `&` in front (`& "…\gamesync.exe" scan`), and GameSync must be quit from the tray before a build, or the build can't replace its files.
- **The owner's own GameSync may be running** from `src\GameSync.App\bin\Debug\net10.0-windows10.0.19041.0` (or `src\GameSync.Tray\bin\Debug`) (no `--data`: it syncs their real saves), which locks that folder, so a full build fails to copy there. Leave it running: build a test copy elsewhere with `dotnet build src/GameSync.Tray -o <scratch>\tray-build` (and `src/GameSync.App -o <scratch>\cli-build` for `gamesync.exe`), and run that with `--data <scratch>`.
- **Look at the real window** by capturing it with `PrintWindow` (`tools\window\capture.ps1 -ProcessId <id> -Out <png>`; the window's title is "GameSync"), and at renders with the Read tool on the PNG files; compare with the design system's screens (`design/system/viewer.html`).
- **Drive the real window** through UI Automation from PowerShell (`tools\window\uia.ps1`, with `UIAutomationClient`): find an element by its name, then `SelectionItemPattern.Select()` for a pill tab (`-Action select`) or `InvokePattern.Invoke()` for a button (`-Action invoke`). It's also a quick screen-reader check: every name should read as a person would say it. Never invoke Play on the owner's PC; it starts the real game.
- **The theme engine's expected values** come from the design system's own JavaScript: `node tests/GameSync.Core.Tests/Fixtures/make-theme-goldens.js` regenerates `theme-goldens.json` after a design-system theme change.
- **Changing the design system** (online, link in `CLAUDE.md`): list its files, read the ones to change, write them under one scratch folder at `project/<path>`, and publish with `root` set to that folder, in one call: the index `project/design-system.json` is the `file_path`, re-read just before, with its `lastChange` updated; `index.d.ts` goes as `{"from": …, "contentType": "text/plain"}`. The service refuses a publish until the artifact itself has been read (`read` with just the `url`) in the session. Never write `tokens.css`: the page makes it. Then copy the changed files into `design/system/` and run `node tools/design-system/refresh.js`, which compiles the local `tokens.css` and rebuilds what `viewer.html` embeds, a new card included (it joins after the last card of its group). Keep the local `README.md`'s snapshot note at its top when copying the online one over it. To look at the viewer, `node tools/design-system/serve.js`.
- **Measuring memory and CPU**: `dotnet-counters` and `dotnet-gcdump` are installed as global tools on the owner's PC; `dotnet-gcdump collect -p <pid>` also forces a full collection, which tells live memory from garbage.
- **Jira** (since 30 Sep): the work is tracked in the KAN project (https://gamesync007.atlassian.net/browse/KAN), an epic per milestone (KAN-4 to KAN-10) and issues named after requirement IDs. Claude calls Jira's REST API with `tools\jira\jira.ps1` (`GET rest/api/3/myself`; `POST rest/api/3/search/jql <body.json>` with a `jql` such as `project = KAN AND statusCategory != Done`); a body is a UTF-8 JSON file, and descriptions are in Atlassian's document format (ADF). ## Gotchas found so far

- **Measure before fixing slowness**: the snapshot tool's `--bench N` renders a page's scrolling with the same CPU Skia as the app (an unchanged frame costs ~4.5 ms, only what changes is redrawn), and `GAMESYNC_RENDER_STATS=1` shows the real window's frame times. Stretching a small picture across the window every frame was 35 ms a frame; `CacheMode` bitmap caches didn't help on the CPU; the GPU (ANGLE) kept ~344 MB private after the window closed.
- **Unit tests can't parse geometry** (`StreamGeometry.Parse` needs Avalonia's render platform): check icons in the snapshot tool's renders instead.
- **A `[ObservableProperty]` field makes a property whose name can clash** with a static method of the same class (`StoreIcon`): name them apart.
- **Fluent's CheckBox has a MinWidth of 120**, so a short one in a tight row clips its own label; set `MinWidth="0"` (the library's Installed box does), and measure: its text needs more room than it looks.
- **A `BoxShadow`'s colour can't be bound or take a `DynamicResource`**: `GsHeroBanner` paints its glow's shadow in code from the theme's `play-color` and again on `ResourcesChanged`.
- **An app job whose result a page needs** goes through `TrayApp.JobAsync` (it returns to the UI thread with the result) rather than `Job`, which only refreshes the pages after.
- **SQLite can't open a data folder whose path runs near 260 characters** (30 Sep): a session started outside the project gets a scratchpad that deep, and `state.db` in it fails with "unable to open database file". Keep scratch data folders under a short path, such as `%TEMP%\claude\E--Games-Tools-GameSync\<session>\scratchpad`.
- **Look before opening a test window** (30 Sep): the rail's library button is named for the game playing ("Game library: Deadlock is running"), and a test copy's agent sees the owner's games run too. If one is playing, don't open windows at all; they come up over the game. Twice on 30 Sep a test window was closed by hand or had to be stopped.
- **A plain property bound with `$parent[…]` is read once, as the page is built** (30 Sep): first run's Add a game folder had no command because `FirstRunPage.AddFolderCommand` was set after `InitializeComponent`, and the folder list hides Add when it has no command. Set such properties before `InitializeComponent`.
- **Settings rows draw a line above every row but the first** (`GsSettingsRow:nth-child(n+2)`), so two rows that take turns in one panel show a line above the second whenever it's the one showing. Give each its own `Panel`, as `CloudChoice.axaml` does.
- **`Progress<T>` in a test has no UI thread to report on**, so a report can land after the work has finished and overwrite what it set. `FirstRunViewModel` ignores reports once the scan is over, and the tests' stand-in scans don't report.
- **Avalonia 12**: a control theme's nested styles can't reach into content (`^:selected c|GsIcon` throws at start). Put such rules in the global styles (`Styles/Type.axaml`) with a class, as `GsIcon.selectable` does.
- **Avalonia 12**: an `Image` sets its own height from its picture; banners use `Controls/GsCoverImage` (CSS `cover`, never sizes its parent) instead.
- **Avalonia 12** needs a text shaper: the app calls `UseHarfBuzz()` (package `Avalonia.HarfBuzz`), or it stops at start with "No text shaping system configured". The headless snapshot tool doesn't need it.
- **Avalonia 12 draws its own tray menus** with the app's theme, so GameSync doesn't use Avalonia's `TrayIcon`: `GameSync.Windows/TrayIcon.cs` calls Shell_NotifyIcon and shows Windows' own menu, which follows Windows (LOOK-11). Its hidden window is a top-level one on purpose: only those hear theme changes and the sign-out.
- **Rendering**: the app uses `Win32RenderingMode.Software`. With the GPU it waited in the tray at about 120 MB and 160 MB after the window closed; with Skia on the CPU, about 70 to 80 MB and 107 MB, looking the same. Revisit only if PERF-03 finds scrolling slow.
- **Memory in a quiet app**: .NET collects rarely when little is allocated, so garbage from a burst of work (the save list parsed for art, a sync) can sit for hours. `TrayApp.LetGoSoon` runs a full collection when the window closes and after background work, at most once a minute. A heap dump showed about 6 MB of live objects when idle.
- **Windows 11 hides a new tray icon** in the overflow (the ^ by the clock) until the person drags it out or turns it on in Settings → Personalization → Taskbar → Other system tray icons. First run should say so.
- **Screen-reader names of list items**: a `ListBoxItem` without a name reads its item's `ToString()`, which for a record is "NavItem { Id = … }". Records shown in lists override `ToString()` with what a person should hear (`NavItem`, `ThemeCard`, `SwatchCard`); give new ones the same.
- **Resources across files**: cross-file references use `DynamicResource`; `StaticResource` only within one dictionary.
- **Glossy swaps brushes, not colours**: `ThemeService.Scope` puts new brushes in the frame's resources, so `DynamicResource` follows but a control that looks a resource up in code when it draws (`TryFindResource` in `Render`) keeps the old colour. Such controls redraw on `ResourcesChanged`, as `GsActivityGrid` and `GsLevelDot` do.
- **A pill with its background under its border** draws an ellipse when its corner radius is larger than half its height (Avalonia clamps the radius in each direction apart); pills give exactly half their height (buttons 20, small ones 16, the chip 13).
- **A style can't hide what a binding shows**: in a control template, `IsVisible="{Binding …}"` on an element outranks a style setter on it (`^:state /template/ …`), so the setter does nothing. Put the condition in the binding (a `MultiBinding` with `BoolConverters.And`, as the hero's chip and blurb do with `HasRoom`).
- **A theme's `MinHeight` beats the layout**: the hero's theme has a 280px least height, which made it overflow the slot `HomeLayout` gave it; Home sets `MinHeight="0"` on its banner, and the layout takes the child's own `MinHeight` into account.
- **Art in a rounded, clipped box**: a ring drawn inside the clip thins out at the corners, where the art's square corner covers it. Rings go on a separate border just outside the art (`Margin="-1"`, the radius one larger), as the tile and hero do.
- **The extended title bar**: `WindowDecorationMargin` changes while the window's XAML loads, before its named parts exist; `MainWindow` sets the Shell's strip after `InitializeComponent` and guards the change. Check the title bar with `WM_NCHITTEST` (the strip should answer HTCAPTION, the buttons HTMINBUTTON, HTMAXBUTTON, HTCLOSE). Maximized, Windows puts the window 8px past each screen edge; Avalonia keeps the content on screen.
- **Borders like CSS**: Avalonia's `Border` draws its background inside the border by default; the edged surfaces set `BackgroundSizing="OuterBorderEdge"` so the background runs under the border, as in the design. Solid's edge tokens are clear (not the surface's colour), so a hovered control never shows a ring.
- **PowerShell** reads a curly apostrophe (’) as a quote mark, so a script that contains one fails to parse. Edit such text with the Edit tool. Windows PowerShell 5.1 also has no `??`.
- **The snapshot tool** needs `UseHeadlessDrawing = false` with Skia for real text and images; `Bitmap.Save(string)` shows an obsolete warning there, which is harmless.
- **Steam's store API** (`IStoreBrowseService/GetItems`): `type` 0 is a game, 6 software, 1 a demo whose `related_items.parent_appid` decides it. The Steam client's cache (`<Steam>\appcache\librarycache\<appid>\`, hashed subfolders too) has 300×450 covers, full-size heroes and logos.
- **Avalonia 12's TextBox** has a new template (`PlaceholderText`, not `Watermark`; parts `PART_TextPresenter`, `PART_InnerDockPanel`), so GameSync keeps Fluent's and styles it through Fluent's own colour keys (`TextControlBackground`, `…BorderBrushFocused` and the rest), aliased to the app's token brushes in `ThemeService.Apply`, so they recolour with the theme; `Classes="clearButton"` gives the clear button. Menus the same way (`MenuFlyoutPresenterBackground`, `MenuFlyoutItemBackgroundPointerOver`, `OverlayCornerRadius`).
- **Never wait on an async read on the UI thread** (`.GetAwaiter().GetResult()` in the snapshot tool hung): its awaits come back to the thread that's waiting. Read on the thread pool (`Task.Run`), as the app does for a game's page.
- **Two things with one name** confuse screen readers and the UI Automation scripts, which find the first match: the rail's Search button is "Search" and the library's field "Search your games".
- **The Bash tool breaks on a heredoc with an apostrophe in it** (`unexpected EOF`): write such a script to a file in the scratchpad and run it, or use the Edit tool. Python edits go to files for the same reason.
- **Avalonia 12 clips by default**: `TemplatedControl`, `UserControl`, `ItemsControl` and `TextBlock` have `ClipToBounds` on, so anything drawn past a control's edge (a hover ring, a glow) is cut, often on two sides only. Set `ClipToBounds="False"` on the control, the list that holds it and its template, and give a scroller room with a negative margin and the same padding inside, as the library does.
- **A `SolidColorBrush` with a `DynamicResource` colour inside a style's setter never resolves** in Avalonia 12: the caption buttons stayed clear. Make the brush in code (`ThemeService.SetBrush`, which recolours the brush already there) and point the setter at it.
- **An `ItemsControl` subclass with its own `ControlTheme` needs a template with an `ItemsPresenter`**, or it shows nothing (`GsFacts` did).
- **Two things with one name, again**: the Properties dialog's close button was "Close", which the UI Automation script found as the window's own close button. It's "Close Properties".
- **Hover states**: render them with the snapshot tool's `--hover x,y`. Posted mouse messages don't hover anything (Avalonia reads pointer messages), and moving the real cursor disturbs the owner; if it must be done, put it back after. PowerShell's `$home` is read only, so a script that saved the cursor in it failed and left the cursor at 0,0.
- **The clipboard**: `SetTextAsync` is an extension method in `Avalonia.Input.Platform`. A path's start matters less than its end: `TextTrimming="LeadingCharacterEllipsis"` keeps the end in view.
- **A button inside a flyout must close the flyout after its command**: Avalonia raises Click before it runs Command, and hiding the flyout in the Click handler detaches the button, which loses its bindings, so the command never runs. `GamePage.CloseFlyoutOf` posts the hide. Every confirm button (Save, Restore, Swap, Keep, Rename) goes through it.
- **Windows' folder and file pickers** open in the app's own process, but UI Automation doesn't expose their Folder (or File name) box for typing: `tools\window\picker.ps1` sends `WM_SETTEXT` to that box (control 1152 in the folder picker, 1148 in the file picker) and `BM_CLICK` to its OK or Open button (control 1), never keystrokes. The picker opens on the last folder used, which may be the owner's Documents: don't read more of it than the controls. A button that opens a picker blocks `uia.ps1`'s invoke until the picker closes: invoke it from a background job (`Start-Job`), then run `picker.ps1`.
- **Pill tabs scrolled their page** (1 Oct): a `ListBox` scrolls its selected item into view when it's selected, and pill tabs have no scroller of their own, so the request went to the page's: Settings' Backup and sync opened scrolled down to its last pill tabs. `GsPillTabs` (and so the settings nav and the theme and swatch pickers) sets `AutoScrollToSelectedItem = false`. A page that opens scrolled for no reason: look for a selected list below the fold.
- **A page that re-reads itself on every refresh** should only replace a list that changed (Settings compares before it sets `Sections`, the folders and the patterns): a new list redraws its items and can move focus.
- **Menu items in Avalonia's flyouts offer UI Automation only ScrollItem**, not Invoke, so `uia.ps1` can't press one (a game's More menu): reach the same thing another way (the gear, then Properties' Art). It's a screen-reader gap to fix with A11Y.
- **Pill tabs are list items**: `uia.ps1 -Action select -Name Local` picks one. An empty argument (`-Title ""`) is dropped by `powershell -File`, so name a real part of the title.
- **A fresh data folder doesn't know Steam's software** until its first art refresh (Steam says an app's type in the same request): until then the agent took Wallpaper Engine, which runs all day, for a game being played. That's why a game that doesn't sync never pauses the agent's disk work, and why the app has the agent re-read its watch list after the art arrives (`AppAgent.WatchNow`). The session it recorded for the software meanwhile only shows in the Software tab.
- **PowerShell names ignore case**: a script's `$window` is its `$Window` parameter, typed as a string. Name them apart.
- **Rendering design cards**: `shoot.js` makes no PNG when run from the Bash tool (Edge headless fails there); run it from PowerShell. The Bash tool's heredocs also turn `\\` into `\`, so write any script with backslashes to a file first. `Set-Content -Encoding utf8` in Windows PowerShell adds a byte-order mark; strip it or write with Python.
- **A real conflict on scratch PCs**: `tools\window\make-conflict.ps1 -Scratch <folder> -GameSync <gamesync.exe>` makes a second scratch PC (LAPTOP) on the scratch data folder's own cloud, plays Lantern Keep on both, and leaves a conflict waiting on DESKTOP (Always ask set in games.json). A session recorded before the last sync correctly doesn't count as play since it.
- **Steam's store**: `IStoreService/GetTagList/v1/?language=english` needs no key (about 16 KB); `GetItems` with `include_basic_info`, `include_release` and `include_tag_count` gives the short description, developers, publishers, release date and tag IDs by weight. Its words come as plain text (no HTML or entities in any of the 55 games asked on 29 Sep); `SteamArt.Clean` takes out control characters, joins runs of white space and cuts to length.
- **A game's page never pulls from the cloud when it opens**: it reads the backup folder's copy of the records, which the agent refreshes every 15 minutes and after every sync; a version another PC made a moment ago shows after the next pull.
