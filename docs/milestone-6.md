## Learn mode's watcher (FIND-04, built 4 Oct 2026)

Drawn first as design system version 43 (GameSavesScreen `#rounds`, `#rounds-playing`, `#rounds-found`, `#rounds-open`, `#rounds-none`; LearnModeDialog; LauncherScreen `#learning`).

- **When it watches**: a game GameSync hasn't found saves for (no proposals from the save list, the engine rules or the name search) and doesn't sync, the next time it's played, however it starts, as first run promised ("No saves found yet · watched the first time you play"). A game's saves page turns it off, or on for any game (a game whose saves went missing too); `gamesync learn <game> --on|--off` does the same. Never a game with an anti-cheat (R15), never Steam's software. Once it has found places, it doesn't watch again until asked (Watch again).
- **What it watches**: the folders saves usually live in (Documents with My Games, Saved Games, AppData's Roaming, Local and LocalLow, ProgramData, Public Documents), Steam's `userdata`, the save folders added in Settings and the game's own folder, with `FileSystemWatcher` (no admin; nothing touches the game, R13). GameSync's own data and backup folders are left out, and names that are never saves (logs, temporary files, crash dumps, program extensions) are dropped as they're heard. At most 100,000 writes are kept; past that, or when Windows reports an overflow, the finds say the list may miss a place.
- **What it finds**: when the session ends (the game closed, 10 s after, as every session), the files written from its start to 30 s past its end are grouped under each watched folder by the folder that names one game (one level; two under My Games and Steam's `userdata`), then narrowed to the deepest folder they share, so an emulator's `user/savedata/1/CUSA00207/SPRJ0005` is offered rather than `user`; a file loose in a watched folder is offered alone. Noise is left out by path (temporary files, caches, shader caches, logs, Microsoft's, Google's, NVIDIA's, Steam's own settings and screenshots under `userdata`), by name, as program files (R1), and as anything the safety guard blocks (R5). Places whose names look like saves come first, then the most written; at most eight. They're kept in `<data>\learn\<game>.json` until the person picks, and a later session's are added to them (Watch again).
- **What the person sees**: while it watches, the game's saves page and Home's banner say learn mode is watching; after, a Windows notification ("ROUNDS: learn mode found where it saves"), the saves page's status line and its Learn mode card with the likeliest places and See what it found, and the game's page. The dialog (LearnModeDialog) lists every place, the likeliest ticked, each checked as Add a place would check it (one it would refuse is locked, with why); Sync these saves adds each ticked place as Add a place does, so the game starts syncing with them; Watch again; Not these. Nothing syncs until the person picks.
- **Command line**: `gamesync learn` lists the games it waits for, watches or found places for; `learn <game>` shows one, its finds numbered; `--add 1,2` adds those places.
- **Not yet**: registry writes aren't watched (Unity keeps PlayerPrefs there; the engine rule finds them at the next scan once the game has made them), and other drives' roots aren't watched unless they're a game's own folder or a save folder added in Settings. The tracer (FIND-05) is what sees writes anywhere.

Checked: `LearnModeTests` (the grouping and the noise on made-up writes; the recorder on a real folder; the stand-in game played with the agent watching, its save proposed after one session and then synced through Sync these saves; R15), 516 tests in all; snapshots `game-saves-learn`, `game-saves-learning`, `game-saves-learned`, `learn-finds` and `library-game` for ROUNDS on the scan of the owner's PC; and the real window, on a scratch copy of that scan with a made-up find: See what it found, a place GameSync's own data folder holds shown locked with why, then Sync these saves syncing ROUNDS to the scratch cloud.

## The installer, the updater and the release signature (built 7 Oct 2026)

Drawn first (design system version 53: SettingsScreen `#updates` and its states, LauncherScreen `#update`), then built:

- **The release key** (R19): `tools/GameSync.Release` makes it (`keygen`, run once on 7 Oct 2026: the private half in the owner's `notes\release-key.pem`, git-ignored, the public half in `src/GameSync.Host/ReleaseKey.cs`), signs a release's installer (`sign`), checks one as the updater does (`verify`) and writes a feed shaped like GitHub's for trying the updater (`feed`). The signature is `GameSync-Setup-<version>.sig`: what it is, the version, the installer's name, size and SHA-256, then an ECDSA P-256 signature over those lines (`Host/Releases.cs`, `ReleaseManifest`).
- **The installer** (PKG-01, PKG-05, R12): `tools/release/GameSync.iss`, built by `tools/release/pack.ps1` with Inno Setup 6 (installed for the owner's account from winget on 7 Oct 2026) beside the zip, then signed. Per user, in `%LOCALAPPDATA%\Programs\GameSync`, no admin prompt; Start menu entry, Windows' installed apps, `gamesync://` links (`GameSync.Tray.exe --link`), the folder on the person's PATH; it asks GameSync to quit before replacing it, and after an update opens it again (`/RELAUNCH`, `/DATA`). Uninstalling runs `gamesync uninstalling` first (`Host/Install.cs`): GameSync quits, and the Run key's GameSync and the daily backup's tasks go only when they start this copy.
- **The updater** (PKG-03, R19; `Host/Updates.cs`): once a day by itself, at once from Check now or `gamesync update [--install [--background]]`; the signature first, the installer hashed as it comes and never past its size, into the data folder's `updates`; Restart to update (Settings → Updates, Home's top bar, the tray menu; not while a game is played) checks it again, held, starts it and quits. Only GitHub over HTTPS; `GAMESYNC_UPDATE_FEED` for a feed on this PC.
- **Links** (R12, `Host/Links.cs`): `gamesync://play/<game>` and `gamesync://open/<game>`, only for a game in this PC's library.

Checked: 592 tests pass, 6 skipped (`UpdateTests` new: the signature and everything it refuses, a release coming down through GitHub's redirects, one changed on the way, bigger than signed, signed with another key or sent from elsewhere, offline and asked again in six hours, the installer checked again as it starts, the notes, links, and the uninstall taking only this copy's start; `SafetyAuditTests.R19_…` runs now, and finds no private key in the repository). Snapshots `settings-updates`, `-latest`, `-downloading` and `-refused`, as the design draws them. And for real on the owner's account (their yes; scratch data, no window, as they were playing): a 0.5.0 test copy installed silently into a scratch folder (its Apps entry, `gamesync://`, PATH and Start menu entry appearing), running in the tray; `gamesync update --install --background` against a feed on this PC found 0.5.1, downloaded its 39 MB, checked it, installed it and had the copy running again in the tray within 9 s, with no prompt; it then said it had the latest; a 0.5.2 changed after signing was refused ("it isn't the installer its signature describes, so it may have been changed on the way") and nothing kept; and the uninstaller ran `gamesync uninstalling`, removed everything it had added and left the test data, the owner's Run key and tasks as they were. The owner's own Start menu shortcut, which the installer's has the same name as, was kept aside and put back. Not tried for real: Restart to update from the app's own window, Home or the tray menu (they start the same installer the same way, then quit as the tray's Quit does), and a release on GitHub itself.
